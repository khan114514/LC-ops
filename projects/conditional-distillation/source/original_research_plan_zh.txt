# 一、先确定论文要回答的问题

## 1. 保留你的方法，但明确两个不同的问题

你的原始构想包含两个有价值的判断：

因此，推荐的完整方法由三部分组成：

| 对老师的蒸馏目标进行条件约束 | 减少监督对身份等条件的破坏 | 建议增加的关键修正 |

最终训练和部署的仍然是**条件学生模型**。老师冻结，只在训练时提供样本和局部预测。

## 2. ICML 的贡献应当落在哪里

- **主张 B：**修正冲突方向，比直接模仿老师、简单丢弃冲突样本、单独加强身份损失更有效。

# 二、任务和模型怎么选

## 1. 主任务采用参考身份控制的视频生成

建议主任务定义为：

> 输入一张人物参考图和动作文本，生成符合该人物身份、执行指定动作的视频。

记：

- \(b\)：老师和学生共享的文本描述；
- \(c\)：学生额外接收的人脸参考条件；
- \(T(x_t,t,b)\)：老师；
- \(S_\theta(x_t,t,b,c)\)：学生。

这里“非条件老师”应准确表述为：**不接收新增身份参考条件的老师**。它仍然可以接收文本 \(b\)。

主实验从已经具有参考身份控制能力的学生 \(S_0\) 开始。研究目标是改善其生成质量、运动和稳定性，同时保持控制能力。这比从零训练身份条件模块更容易隔离蒸馏的贡献。

## 2. 推荐模型组合

| 用途 | 老师 | 学生 | 选择理由 |
|---|---|---|---|
| 主实验 | Wan2.1-T2V-1.3B | Concat-ID-Wan-AdaLN | 同一基础模型体系，便于对齐状态和预测；适合先完成低成本验证 |

开始正式训练之前，先核对 VAE、时间步、预测参数化、参考 token 和生成区域的对应关系。老师与学生可以接收不同形式的条件输入，但蒸馏必须比较同一生成区域、同一噪声状态下可对应的预测。

# 三、数据到底需要什么，以及怎么构建

## 1. 不需要老师随机生成指定的外部人物

训练时的流程是：

\[
x_0^T\sim p_T(x\mid b),
\qquad c=h(x_0^T).
\]

老师生成某个人的视频，我们再从中提取这个人的参考图。于是得到：

\[
(\text{文本 }b,\ \text{参考条件 }c,\ \text{完整视频 }x_0^T).
\]

例如，老师生成了人物 A 的视频，就用人物 A 的参考图训练学生。测试时输入真实参考人物 B，学生独立生成，老师不参与。

这里需要验证的是学生对外部参考条件的泛化；**不需要老师先随机命中 B**。

同时要区分：训练对中的条件一致，不代表老师后续每一步都会保持这个条件。后者由局部目标修正和相应实验处理。

## 2. 建议的数据规模

以下数量均指**经过过滤后的有效样本**。

| 数据部分 | 建议规模 | 用途 |
|---|---:|---|
| 最小训练集 | 128 条老师视频 | 检查数据、梯度和训练闭环 |
| 最小开发集 | 32 条老师视频 | 快速发现错误 |
| 第一阶段训练集 | 2,048 条老师视频 | 比较主要方法，筛选超参数 |
| 正式训练集 | 8,192 条老师视频 | 主实验 |
| 合成开发集 | 256 条老师视频 | 选择检查点和超参数 |
| 合成机制测试集 | 256 条老师视频 | 冲突分析、局部干预和轨迹实验 |
| 外部开发集 | 每个域 32 个参考身份 | 校准阈值和生成配置 |
| 外部测试集 A | CelebV-HQ 中 100 个身份或经过核验的身份簇 | 视频来源的人物参考 |
| 外部测试集 B | FFHQ 中 100 个身份簇 | 静态照片来源的人物参考 |

正式外部测试为：

\[
2\text{ 个域}
\times100\text{ 个身份}
\times4\text{ 个提示词}
\times2\text{ 个生成种子}
=1,600\text{ 条视频/检查点}.
\]

训练集采用嵌套子集：

\[
512\subset2,048\subset8,192,
\]

便于画数据效率曲线。

**一个完整老师视频是一个基本数据单元。**从同一视频裁出多张脸、重复加噪多次，都不能计为更多独立身份或更多独立目标视频。

## 3. 老师视频的生成与过滤

先限制到容易分析的场景：单人、近景或半身、少量基础动作。动作可以覆盖转头、微笑、眨眼、点头、简单手部动作，再逐步加入光照和背景变化。

每条候选视频经过以下处理：

1. 检查能否解码，帧数、尺寸和帧率是否正确。
2. 检查是否为单一主要人物，是否发生切镜或人物替换。
3. 检查跨帧身份是否稳定。
4. 检查是否完成文本要求，是否只有静止画面或重复帧。
5. 检查严重脸部、手部和时序伪影。
6. 按动作、姿态和质量分层，人工抽查至少 100 条。

必须记录过滤前后的数量及原因。若有效率为 \(r\)，生成预算应按：

\[
N_{\mathrm{raw}}\approx N_{\mathrm{accepted}}/r
\]

估计，不能把 8,192 条有效样本等同于只需生成 8,192 次。

## 4. 参考条件如何提取，避免走捷径

优先方案是：

> **参考图来自完整视频中不属于训练目标时间窗口的帧。**

例如，用片段前部的清晰人脸作为参考，训练学生生成后部时间窗口。这样能减轻学生直接复制目标帧的倾向。

还需要做到：

- 参考图与目标视频分别编码，避免视频 VAE 的时间信息泄漏。
- 每个视频可以保存 2–3 张候选参考，但一次更新只选一张，整个局部轨迹固定使用它。
- 如果只能从目标片段内取参考，则把对应目标帧排除出身份损失，并单独做消融。
- 不把未经核验的两条老师视频当作“同一个人、不同动作”的训练对。

一个老师视频中的身份和动作天然绑定。因此，不能仅凭多次加噪就认为获得了“同一人物执行多种动作”的充分监督；这也是采用已有条件学生、并设置外部动作泛化测试的原因。

## 5. 数据划分与外部来源

划分单位必须包含原始视频、近重复关系和身份簇。不能把同一人物的不同裁剪随机分到训练集与测试集。

CelebV-HQ 可以提供视频参考来源，但公开元数据不能直接当作完整、无误的身份划分；其仓库还明确了研究用途和原始数据再分发限制。FFHQ 需要保留逐图来源与许可信息，也不能默认“一张图就是一个不同身份”。[GitHub](https://github.com/CelebV-HQ/CelebV-HQ?utm_source=chatgpt.com)

建议公开的是划分 ID、下载和处理脚本、过滤规则、提示词、种子及配置，是否发布原始内容按各来源许可处理。

测试中的“未见身份”应限定为：**未参与本次蒸馏训练和调参的身份**。不声称它们从未出现在基础模型的预训练中。

# 四、推荐的完整训练方法

## 1. 保留你的采样顺序

每次更新分为两个分支。

**配对训练分支：**

从完整老师视频重新独立采样噪声：

\[
z_t=\alpha_t x_0^T+\sigma_t\epsilon,
\]

使用标准 diffusion/flow 训练目标，训练学生根据 \(b,c\) 预测。噪声不绑定老师原始生成时的随机种子。

**混合轨迹分支：**

1. 从老师视频重新加噪得到起点；
2. 老师走一步；
3. 学生带着固定条件 \(c\) 走 \(k\) 步，默认 \(k=1\)；
4. 在学生到达的新状态上，查询老师和学生；
5. 构造蒸馏目标，只更新学生。

轨迹生成阶段停止梯度，训练时无需反传整条 rollout。

有一个必要的公平性要求：**先确定最终接受监督的时间步，再向前安排老师一步与学生 \(k\) 步。**否则比较 \(k=0,1,3\) 时，可能同时改变了监督噪声水平，无法判断收益来自 rollout 还是更容易的时间步。

这个要求同样适用于混合轨迹与完整学生轨迹的比较。

## 2. 不直接把老师预测作为最终目标

在同一个查询状态，把老师和学生的预测转换成干净 latent 预测：

\[
y_T,\qquad y_S.
\]

定义条件误差：

\[
E_c(y)=D\big(F(\operatorname{Decode}(y)),c\big),
\]

其中 \(F\) 是冻结、可微的身份特征提取器。

理想目标为：

\[
y^*=
\arg\min_y\|y-y_T\|^2
\]

满足：

\[
E_c(y)\le E_c(y_S)+\delta,
\qquad
\|y-y_S\|\le r.
\]

它的含义是：在有限的更新范围内，尽量靠近老师，同时限制条件误差的增加。

## 3. 用简单近似实现，先不要堆复杂求解器

令：

\[
d_0=y_T-y_S,\qquad
g=\nabla_yE_c(y_S).
\]

当 \(g\) 可靠且非零时，使用：

\[
d=d_0-
\frac{\max(0,g^\top d_0)}
{\|g\|^2}g.
\]

这样去掉了老师方向中一阶上会增加条件误差的分量。

之后进行半径裁剪，并依次测试步长 \(1,\frac12,\frac14\)。选择满足实际条件检查的最大步长：

\[
E_c(y_S+a d)\le E_c(y_S)+\delta.
\]

若都不满足，跳过该样本的局部蒸馏，但仍保留配对训练。

这里有三个需要明确的限制：

- 约束的是身份代理指标，不能当作真实身份的完美保证。
- 约束的是构造出的目标，不能直接保证一次参数更新后的模型表现。
- 靠近老师预测不自动等于最终画质提升。

因此，实验必须分别观察**目标构造、有限次拟合、完整视频生成**三个阶段。DiffusionOPSD 的结果也提示，目标层面的改善不一定在有限次拟合后完整实现。[arxiv.org](https://arxiv.org/abs/2608.24646?utm_source=chatgpt.com)

## 4. 总损失与实现边界

建议采用：

\[
\mathcal L=
\mathcal L_{\mathrm{pair}}
+\lambda_c\mathcal L_{\mathrm{cond}}
+\lambda_{\mathrm{KD}}\mathcal L_{\mathrm{KD}}.
\]

其中：

- 配对损失提供稳定的条件生成监督；
- 条件损失保持身份；
- 蒸馏损失拟合经过修正的老师目标。

实现时尤其注意：

- 经过老师或学生 rollout 后，不能继续把最初加噪用的 \(\epsilon\) 当作该新状态的正确标签。
- 在干净 latent 空间修正后，要正确转换回模型原生的噪声预测或 velocity 参数化。
- 身份梯度必须穿过可微解码与识别过程；常见 ONNX、NumPy、PIL 路径可能切断梯度。
- 梯度只用于构造停止梯度的目标，不引入不必要的二阶梯度。
- 参考 token、固定首帧等非生成区域不能混入蒸馏误差。

# 五、从最小验证到正式实验的顺序

## 阶段 0：兼容性与成本核验

先完成模型加载、条件输入、预测转换、单次更新和独立推理。

用 5 次预热和 20 次完整更新测量时间与显存，测量必须包含 VAE 解码、身份梯度和目标检查。不能只测一次 DiT 前向，就据此估算整项研究。

**产出：**兼容性记录、单步成本、最小可运行训练配置。

## 阶段 1：低维实验，验证冲突机制

构建二维高斯混合分布：

- 混合分量对应条件；
- 无条件和条件 score 可以精确计算；
- 比较直接蒸馏、门控、投影、混合轨迹和完整学生轨迹；
- 使用已知条件 score 作为机制分析的理想参考。

起始配置为 20,000 个训练样本、10,000 个测试样本、5 个训练种子。

**产出：**向量场、轨迹、条件错误率、模式覆盖及分布误差。它用于排查理论和实现问题，不能替代视频实验。

## 阶段 2：不训练或少量训练的局部干预实验

在相同查询状态分别执行：

- 学生原始一步；
- 老师原始一步；
- 门控后的老师一步；
- 修正后的老师一步。

随后都由同一个学生完成剩余生成，比较最终身份、动作和质量。

这个实验回答：

> 老师的局部更新是否真的存在可利用的收益？它又在哪些噪声水平破坏条件？

若老师在这些状态上几乎没有正向价值，需要先调整模型或适用噪声区间，暂不扩大训练。

## 阶段 3：128 条数据的小规模训练

先运行约 200 次更新，检查：

- 学生是否继续使用参考条件；
- 蒸馏是否几乎全部被拒绝；
- 输出是否变静止或复制参考图；
- 改善是否只在老师提供起点时存在；
- 学生从纯噪声独立生成是否仍然有效。

## 阶段 4：2,048 条数据筛选

开始比较主要方法，初始训练上限约 1,000 次更新。

统一采用 LoRA 起步，例如 rank 16、alpha 32，学习率以 \(10^{-5}\) 为中心，在开发集上有限搜索。所有方法使用相同可训练模块和相同调参预算。

## 阶段 5：8,192 条数据正式实验

正式方法采用 3 个独立训练种子，初始训练上限约 3,000 次更新。开发集选择检查点后锁定测试配置。

之后完成外部测试、人工评价、关键消融、第二模型与第二条件任务。

# 六、正式实验需要哪些对照

主实验包含原始学生，以及以下 **八种需要训练的方法**。

| 编号 | 方法 | 主要回答的问题 |
|---|---|---|
| S0 | 原始条件学生 | 相对起点有没有改善？ |
| P | 仅配对训练＋条件损失 | 收益是否只是来自老师生成的数据？ |
| H0 | 你的混合轨迹＋原始老师目标 | 原始构想本身能否成立？ |
| H1 | 混合轨迹＋条件门控 | 丢弃冲突监督是否已经足够？ |
| H2 | 混合轨迹＋受约束目标修正 | 推荐的完整方法 |
| O0 | 完整学生 rollout＋原始老师目标 | 普通学生轨迹上的蒸馏表现如何？ |
| O1 | 完整学生 rollout＋同样的目标修正 | 老师起点是否还有额外价值？ |
| C-H | 与 H2 相同的混合状态和共同损失，移除 KD | 收益是否来自混合状态上的身份损失？ |
| C-O | 与 O1 相同的学生状态和共同损失，移除 KD | 完整学生轨迹上的收益是否也来自身份损失？ |

**C-H 和 C-O 是必要对照。**否则 H2 比 P 好，也可能只是因为多加了在线状态上的身份监督。

比较时需要同时给出：

- 相同训练更新次数；
- 相同实际训练计算预算；
- 相同推理步数和生成设置。

若只比较训练步数，完整学生 rollout 方法可能消耗更多计算；若只比较时间，又可能隐藏样本效率。两种视角都应报告。

## 最关键的消融

| 消融 | 设置 | 排除的替代解释 |
|---|---|---|
| 状态来源 × 目标修正 | 混合/完整学生轨迹 × 原始/修正目标 | 分离轨迹与目标两项贡献 |
| 老师起点 | T→S 对比 S→S | 起点收益是否只是多走一步 |
| 学生 rollout 长度 | \(k=0,1,3\)，最终查询时间一致 | 学生局部行为是否必要 |
| 门控与投影 | 原始、门控、投影、投影＋实际检查 | 具体哪一步有效 |
| 弱蒸馏 | 降低原始 KD，匹配实际梯度强度 | 是否只是把老师权重调小 |
| 随机门控 | 按噪声区间匹配接受率 | 是否只是减少监督数量 |
| 仅条件方向 | 去掉老师方向，只用条件梯度 | 老师是否提供了额外信息 |
| 参考构建 | 同帧与窗口外参考 | 是否存在复制捷径 |
| 重新加噪 | 独立噪声与原始轨迹绑定 | 是否记住老师轨迹 |
| 数据规模 | 512、2,048、8,192 | 数据效率和饱和情况 |

敏感性实验还应覆盖噪声区间、目标半径、条件容差、损失权重和身份特征模型。先在开发集单种子筛选，支撑主要结论的设置再进行三种子确认。

# 七、评价协议怎样才可信

## 1. 主测试必须让学生独立完成生成

测试过程固定为：

> 外部参考图＋文本＋新噪声 → 学生完整生成。

不能给学生老师生成的前缀，不能把老师继续完成的视频算作学生结果，也不能只报告训练时抽取的合成身份。

同时设置两个条件使用实验：

- 固定噪声，替换参考身份：输出身份是否跟着变化？
- 固定参考身份，替换噪声：能否保持身份，同时产生合理的动作和画面变化？

这样才能区分条件控制、身份记忆和简单复制。

## 2. 指标分开报告

| 维度 | 建议指标 |
|---|---|
| 身份控制 | 独立识别器相似度、身份通过率、跨帧身份跳变 |
| 视觉质量 | 成像质量、审美质量、严重伪影率 |
| 视频质量 | 运动平滑性、闪烁、主体稳定性 |
| 动作与文本 | 指定动作完成率、文本匹配 |
| 失败情况 | 人脸检测失败、人物替换、静止复制、严重崩坏 |
| 多样性 | 身份通过前提下的姿态、运动和非身份外观变化 |
| 人工评价 | 质量偏好、身份保持、动作完成 |

VBench 可以提供部分视频质量维度，但主体一致性分数不能代替“是否是参考人物”的身份评价；对于自定义视频，还要使用它实际支持的相应评测维度。[We Evaluate Video Generation · GitHub](https://github.com/Vchitect/VBench?utm_source=chatgpt.com)

训练和评价的身份模型应独立。例如，训练使用可微 ArcFace 实现，评价使用独立权重的 AdaFace，并严格分别遵循各自预处理要求。AdaFace 官方实现可作为评价候选。[mk-minchul/AdaFace · GitHub](https://github.com/mk-minchul/AdaFace?utm_source=chatgpt.com)

建议每条视频均匀抽取 16 个生成帧。身份阈值在开发集校准；预设视频通过规则，例如至少 90% 的评价帧通过身份与有效检测检查。检测失败计入分母，不能删掉难帧后只算成功帧。

背脸、遮挡等场景另设压力测试，重点观察重新出现后能否恢复身份。

## 3. 人工评价

建议抽取 200 个配对案例，两个外部域各 100 个，分别比较：

- H2 对 P；
- H2 对 O1；
- H2 对 H0。

每对由 3 名评价者独立判断，左右随机，允许平局，分别回答质量、身份和动作三个问题。

对应：

\[
200\times3\text{ 组比较}\times3\text{ 人}
=1,800\text{ 次成对展示},
\]

合计 5,400 个分项判断。

案例预先在三个训练种子间平衡分配，避免挑选最好的单个检查点。

## 4. 统计方式

正式结果报告三个训练种子的单独表现及均值、标准差。方法比较使用按身份聚类的配对 bootstrap；不要把同一人物的多个帧当作独立样本。

两个外部域分别报告，再给等权汇总。质量提升应同时满足预先规定的身份和动作非劣要求。

所有阈值、选择规则和主要指标都在开发阶段固定。看过测试结果后再改方法，就需要新的确认集，或者明确标注为探索性分析。

# 九、为了支撑 ICML，还应做怎样的泛化实验

第二个视频模型验证的是**跨架构**；两个外部人脸数据域验证的是**跨数据域**。它们都不能独立证明方法适用于不同条件任务。

因此，建议增加一个成本较低的第二任务：

> 文本生成图像老师 → Canny 边缘条件学生。

选择同一基础模型对应的已有 ControlNet 学生，仍然采用：

- 老师生成图像；
- 从图像提取边缘条件；
- 老师起点＋学生局部 rollout；
- 条件约束目标修正。

起始规模可以是 8,192 张老师图像、512 张开发图，以及 500 张来源和许可已核验的外部测试图。

训练使用可微的软边缘误差，测试使用独立固定的硬边缘提取与边缘匹配指标，同时报告图像质量。

这项实验尤其有用：它能判断方法是否只依赖人脸识别器。如果第二任务不成立，就把论文结论限定为身份控制视频蒸馏，不强行声称通用条件生成框架。

第二视频平台也应生成自己的老师训练对，先从 2,048 条开始。不能直接复用第一平台的数据，就把结果称作完整流程的跨模型验证。

# 十、成本、推进顺序与停止条件

## 1. 正式测试的实际规模

主实验八种训练方法，每种三个训练种子，每个检查点生成 1,600 条视频：

\[
8\times3\times1,600=38,400.
\]

再加原始学生 S0 的 1,600 条：

\[
\boxed{40,000\text{ 条主测试视频}}.
\]

这还不包括开发集、局部干预、额外权衡曲线操作点、关键消融和第二平台。

预算有限时，可以先把每域测试身份从 100 个减至 50 个，主测试数量相应减半，但置信区间会更宽。优先缩减探索性网格，保留能够判断贡献来源的关键对照。

我不建议现在直接承诺“几张 GPU、几天完成”。先测完整更新和完整生成的成本，再按上述数量估算；条件梯度和解码开销可能显著改变预算。

## 2. 建议的工作包

| 工作包 | 主要工作 | 必须产出的结果 |
|---|---|---|
| W0 | 模型兼容、单步训练、成本测量 | 可运行闭环与资源记录 |
| W1 | 二维实验、视频局部干预、128 条试训 | 是否存在可利用的老师方向 |
| W2 | 构建 2,048 条数据、过滤和划分 | 固定数据版本与开发协议 |
| W3 | H0/H1/H2 和损失归因对照 | 哪个构件真正有效 |
| W4 | 八方法三种子、外部测试、人工评价 | 主结果和关键消融 |
| W5 | 第二模型、第二任务、图表与复现材料 | 结论适用范围与投稿材料 |

## 3. 哪些结果出现时，应当缩小或改变主张

| 观察结果 | 应作出的研究判断 |
|---|---|
| 老师局部更新没有稳定质量收益 | 先检查平台或噪声区间，不急着扩大训练 |
| H2 与 P 相当 | 收益可能主要来自合成配对数据 |
| H2 与 C-H 相当 | 收益可能主要来自在线条件损失 |
| H2 与弱 KD 相当 | 修正可能主要起到降低蒸馏强度的作用 |
| H2 与仅条件方向相当 | 老师方向没有表现出额外价值 |
| H2 与 O1 相当 | 混合轨迹的优势可能只在成本或效率 |
| 只有老师提供前缀时有效 | 尚未实现可独立部署的学生 |
| 身份上升但视频静止、动作失败 | 条件指标存在捷径，不能判为成功 |
| 训练识别器改善、独立识别器不改善 | 可能在适配代理指标 |

**最值得优先投入的是 W1 和 W3。**前者决定老师是否确实提供了可以迁移的局部收益；后者决定你的混合轨迹和目标修正是否超出了“更多数据、更多身份损失、较弱蒸馏”的解释。把这两个环节做扎实，再扩展到完整三种子、多平台和多任务实验，才能让论文的主要结论由证据支撑。
