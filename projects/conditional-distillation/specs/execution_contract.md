# AutoResearch 执行与完成契约

契约版本：`autoresearch-execution-v1`。适用于接收者明确要求实际执行本项目以后；阅读、审查或维护交接包不启动研究。方法范围以 [方法搜索与选择](method_search_and_selection.md) 为准；原OPD/投影是初始候选。数据和评分细节仍以各任务规范为准。本文件统一总控循环、任务归属、阴性关闭与最终状态，取代旧“交付诚实初稿即可结束”的歧义。所有未执行状态仍如实保留。

## 启动输入与工程就绪

1. 定位真实项目根，检查现有 owner、用户暂停记录、真实 jobs 和历史产物。新项目才初始化；恢复不清空状态、不重复 launch。模板 `paused=null` 不是“已核验未暂停”。本次明确启动且无历史暂停/在途任务时可初始化为 false，已有暂停仅按用户明确继续指令恢复。
2. 读取 project.yaml.resources 和 state/resource_plan.json，复用已授权 host/device/scheduler、并发、GPU 小时、墙钟、存储和费用限额。null 不是无限额度。小规模 GPU 成本测量也需要已有额度；先明确测量额度，再用测量规划后续阶段。
3. 按任务核验 teacher、条件学生、VAE/scheduler、训练代理、独立评价器和数据的真实入口、版本/checksum、许可、可访问状态。不能只凭候选名称宣称兼容。不要扫描私人目录或其他项目寻找访问凭据。
4. 工程角色实际实现缺少的 setup、数据处理、trainer、sampler、metrics、统计与恢复入口。保存可运行命令和环境锁定；不要停在接口草图，不编造不存在的 CLI。包内 scripts 是辅助工具，不是已经跑通的训练项目。
5. 能自行检查或实现的缺项直接处理。必须由用户提供的资源/预算/访问输入合并提问，同时继续独立工作。目标会议年份不阻塞算法实验；人工评价若是冻结协议必需而缺真实评价者，则保留相应外部阻断。不能用 AI 冒充人评，也不能事后为结束任务取消人评门槛。

结构检查 PASS 只证明该脚本覆盖的结构/链接。每任务实际 G0 还需要一个真实 batch 的加载→目标构造→反向→参数更新→保存→新进程重载→外部条件和新噪声独立生成，以及候选实际使用的参数化、mask与梯度边界证据。只有直接同状态蒸馏的候选要求双方同状态/兼容坐标；未采用的专用步骤注明NOT_APPLICABLE并给与该候选相符的验证，不强套OPD。CPU/mock 检查不能替代真实模型链路。

## 任务、目录与状态写入

- 正式实验 `task_id` 为 T1/T2/T3，路径 `runs/<task_id>/<run_id>/`。三任务各自 G0–G4，不因另一个任务未成功而阻断准备或合规执行。可选第二视频架构属于 T1。
- 辅助二维机制使用 `task_id=TOY`、`execution_kind=toy`、`runs/TOY/<run_id>/`，其证据层级为 simulated；它不是第四个正式任务，不满足任何任务的真实模型 gate。
- 文献/论文/跨任务审查等非实验 assignment 使用 `task_id=null` 与明确的 `task_ids` 列表，run_ids 可空。实际实验 assignment 必须指定单一 task_id，不能把多个任务的结果混为一个 run。
- assignment 字段见 [模板](../templates/assignment.example.json)。共享状态由唯一总控写入；worker 只写授权目录与报告。模板是字段示例，不是已派工或验证的记录。
- state/method_search.json同样由总控唯一写入；当前候选、选定协议和活动矩阵写入每个相关assignment/run，模板含candidate_id。状态更新采用原子写入，保留 decisions.jsonl 的追加记录。确认唯一 owner 后才写；跨主机需明确移交并确认旧 owner 不再写，不能只凭心跳/租约超时夺取控制或杀作业。保留现有键，契约变更由总控版本化，不让 worker 各自修改 schema。
- 旧 run 保留真实路径和元数据；协议/代码/配置/数据有实质变化时新建 run 并关联原记录，不倒填新 hash。租约过期或日志停更不等于进程已结束；失联标 unknown 并调查，不能重复启动。

## 成本、限额与公平比较

每任务按 method×硬件/配置测完整更新成本，包含 rollout、teacher query、VAE Decode、条件梯度、回溯和同步计时。P/H/O/C、不同 k 和图像/视频任务不能共用未经验证的单步时间。5 次预热＋20 次完整更新是建议测量方案，调整须记录理由与测量范围。

使用 `scripts/cost_plan.py --method-costs <已填写的成本表>` 分别求和；格式与完整性规则见 [成本说明](../scripts/README.md) 和 [空白模板](../templates/method_costs.example.json)。旧标量 CLI 仅作显式的单一成本简化估算，不用于正式预算和 compute-matched 选择。未知成本保持 null；未测配置只能用有证据且明确标注的保守上界，不能自动退回其他方法耗时。

方法级训练总和仍不包含全部费用。资源计划还须计入老师数据和过滤、开发、消融、额外 update/compute 检查点、测试生成、评价、重试、存储与人评。T1 40,000 视频、T2/T3 各 50,000 图仅是一个开发选定检查点/推理操作点的主测数。显式方法矩阵通过成本表required_methods声明，覆盖检查针对该矩阵，不锁死初始八方法。每个真实 job 启动前扣查剩余额度，把墙钟和适用资源限制落实到实际调度器/本项目进程管理，而非事后才查超额。

预算不足时按已有授权在测试暴露前冻结缩小协议，列与原矩阵的差额及统计损失；不能静默减少方法/seed 或把缩水协议称为完整协议。compute-matched 比较依据各方法真实累计完整成本选择 checkpoint，不能用估算器替代运行日志。

## 总控持续循环

初始化后重复以下步骤；文档写完、任务派出或训练启动都不是结束条件：

1. 核对暂停、剩余预算、真实 jobs/worker 状态和新报告，优先处理失败与到达检查点的作业。
2. 验收真实退出状态、产物、版本、指标分母和报告，合并已完成工作，释放确认已结束的租约。消息“完成”不是证据。
3. 在依赖/gate 满足、预算允许的工作中选择最有信息价值的下一项，先写冻结协议和 done gate，再执行或派工。阶段通过后直接推进授权范围内下游，不等用户再说“继续”。
4. 对故障按区分根因的最小检查修复，保留旧失败 run；对科学阴性按下节判定，不无限调参寻找正结果。
5. 只剩在途工作时，用实际可用的 job/subagent/chat 等待工具有界等待，并处理可并行的独立工作。按宿主能力拉长无变化检查间隔，避免空转。没有并行工具时总控串行执行，不能只交手工派工卡就结束。
6. 有新证据时更新研究综合、claim→evidence、论文和下一步决策。论文可以先有 PENDING 稿，但有可执行实验时不能把它当项目交付终点。

用户暂停就停止新派工并记录在途作业；不擅终止别人的进程。宿主强制中断时保存状态、预算、job、checkpoint 和下一条真实命令，标 INTERRUPTED。当前未授权定时自动化；prompt 不能保证客户端关闭后的自动唤醒，不伪称仍在持续运行。

## 阴性分支与独立修复闭环

在看到对应结果前，为每任务冻结可行性、停止扩展规则、最小证据量、指标、失败处理、不确定性及诊断预算。若候选机制无可用收益，先排除适配/指标故障，再用独立确认数据或局限明确的复核判断。原家族的老师局部价值门只关闭相应candidate×task分支；只有对问题范围内已承诺探索的候选完成合理筛选/复核后，才可据限定证据关闭整个任务，不能由一个OPD失败推出所有方法无效。证据不足为 INCONCLUSIVE；不显著不等于等价或无效。

满足事前停止规则且经独立审查的任务可标 `CLOSED_NEGATIVE`，保存原始结果、复算、范围和停止依据。后继矩阵逐项记录 `NOT_RUN_WITH_REASON`，gate 仍为 NOT_RUN，并关联关闭报告；不得把跳过的 G2–G4 标 PASS。其它任务继续。由此形成的科学结论可作为研究产出，但不等于全量三任务实验完成。

独立 QA 面向同一最终代码/配置/数据/论文快照和原始证据。总控逐项分派实质问题修复、复算受影响结果，再交复核。审查者不自己修改被审实现；没有独立审查能力时保留缺项，不能伪造独立 PASS。负结果不需要修成正结果；错误、证据缺失和过强主张需要处理。

## 最终状态与交付

总控在 `reports/completion_report.json` 及 Markdown 报告记录 project_outcome，字段见 [完成报告模板](../templates/completion_report.example.json)。assignment 完成、paper_status 与 project_outcome 分开；template/null 不代表完成。

| project_outcome | 必需条件与报告口径 |
|---|---|
| FULL_PROTOCOL_COMPLETED | T1/T2/T3 完成选择后、测试前冻结的完整正式协议（方法改变不等于缩水）及必要归因/人评，原始结果可复算、实质 QA 问题关闭、论文与证据一致；结果可正可负。不能用缩水或提前停止任务满足此状态。 |
| SCIENTIFICALLY_CLOSED_WITH_EARLY_STOPS | 至少一任务按事前规则经独立复核关闭阴性分支；其余任务完成各自完整闭环或同样合规关闭，无外部缺项被掩盖。列未执行矩阵，只称研究已形成结论，不能称全量实验完成。 |
| REDUCED_SCOPE_COMPLETED | 测试前冻结的缩小协议已完成、实质 QA 问题关闭，所有差额/提前停止/统计限制明确；原完整协议仍未完成。缩小协议与提前停止混用时采用此状态并逐任务披露。 |
| PARTIAL_BUDGET_STOP | 全局或事前阶段/诊断预算到界且冻结协议尚未完成；保留已完成/未完成/在途状态和继续所需资源。 |
| BLOCKED_EXTERNAL | 必要资源、访问、模型或人评/独立审查条件缺失，且所有不依赖它的已授权工作已做完；不是研究完成。 |
| PAUSED / INTERRUPTED | 分别为用户暂停和宿主中断；保留恢复条件，不自动当作完成或恢复授权。 |

若预注册诊断/筛选阶段额度已用尽仍为INCONCLUSIVE，总控先判断能否在原授权范围内按事前规则重新分配未使用额度；不能无限追加或事后改变成功标准。无法合理继续时记PARTIAL_BUDGET_STOP并注明是阶段额度/信息不足，即使全局尚有余额也不伪称阴性关闭；保留剩余额度和下一项最有信息价值的实验。

逐任务记录结论状态 `EMPIRICAL_COMPLETE / CLOSED_NEGATIVE / INCONCLUSIVE / INCOMPLETE`、协议、gate、原始 run、独立复核、未执行行和限制；缩小协议的 EMPIRICAL_COMPLETE 仅指该声明范围。全局状态必须由这些记录及交付情况推导，不能只因文件存在或论文编译成功而完成。

最终交付：代码/环境锁定与真实命令、模型/数据/许可清单、全部成功失败 run、检查点与哈希、逐样本指标及统计脚本、三个任务的 gate/主张/未执行表、图表与证据映射、实际消耗、复现说明、英文论文源码与实际编译状态、独立 QA 及修订记录。缺实验/编译/人评分别披露，公开上传与投稿需另外的实际授权。
